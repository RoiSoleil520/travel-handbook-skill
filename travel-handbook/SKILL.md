# 旅行手册网页

将自然语言攻略整理成数据，再用内置模板生成网页。沿用模板的样式与交互，不重新设计页面，不让用户填写大型配置表。

## 工作流程

1. 读取用户给出的攻略、文件或已有对话，提取目的地、出发日期、同行人及每天安排。只有缺少目的地/城市或起始日期时才简短追问；其余缺失内容写“待确认”或留空。没有明确日期的真实出行，不擅自指定日期。
2. 阅读 [数据格式](references/data-format.md)，将信息写入工作目录中的 `trip.json`。基础信息使用 `title`、`startDate`、`timezone`、`travelers`、`days`；嵌套结构和可选功能按数据格式填写。标题可从目的地和天数生成，时区使用目的地对应的 IANA 名称，每日日期可从起始日期逐日派生。保持原有每日顺序；用户没有给时间时留空，使用 `label: "时间待定"`，不擅自添加活动、时间、价格、航班号或已购状态。
3. 有图片时，优先使用用户提供且可分享的文件；图片路径填写 `assets/custom/文件名`。没有图片时使用模板占位图，并保留“示意”说明。来源或授权要求署名时保留署名。不要复制私人订单、原攻略 PDF、登录凭据或其他无关数据。
4. 从本 skill 所在目录执行生成命令，输入和输出路径换成实际工作目录路径。输出使用新目录，避免覆盖用户已有网页：

   ```sh
   node scripts/build.mjs --input <trip.json> --output <新目录>
   ```

   自带图片时增加参数，`--assets` 指向包含上述图片文件的目录：

   ```sh
   node scripts/build.mjs --input <trip.json> --output <新目录> --assets <图片目录>
   ```

5. 执行 `node tests/check.mjs`。启动本地静态服务预览输出目录，检查封面、日期切换、每日时间线、景点详情与返回、地图/复制地点、待办保存及手机/桌面布局；只有数据包含相应内容时才检查角色切换、备选方案、航班倒计时等可选交互。可选浏览器自动检查需要 Playwright。
6. 交付完整输出目录、预览方式及尚待确认的信息。需要分享这个 skill 时，交付整个 `travel-handbook` 目录，不单独交付 `SKILL.md`。用户未要求时不安装到全局、不发布网站。

## 模板与数据边界

- 保留深绿/浅纸绿配色、摄影封面、日期条、时间线卡片、手机底部旅行工具、桌面侧栏以及原有键盘与触屏交互。
- 行程时间按活动所在地显示；预览时间应有清晰提示，航班倒计时只表示计划时间，不表示实时航班状态。
- 航班、酒店、接送和预约的购买/确认状态必须来自用户提供的信息；未知状态标记待确认。
- 待办与偏好保存在当前浏览器。离线功能需通过 HTTPS 或本地服务打开，并首次联网加载；地图等外部服务仍需网络。
- 本模板不内置账号鉴权和多人云同步。输出是明文静态文件，本机保存也不等于加密。交付前检查是否含用户不希望公开的个人或订单信息。
- 脚本和模板均相对本 skill 目录定位。不要写入作者机器的绝对路径，或把另一次旅程的数据带入新页面。
